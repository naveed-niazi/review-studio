### What's new

- **Automatic recovery for failed reviews.** Failed reviews are checked again after five minutes by default. Open PRs that still need a review return to the queue; merged, closed, and superseded reviews are skipped. Recovery is limited to three additional attempts per review within 24 hours.
- **Faster detection of stalled reviews.** A configurable inactivity timeout stops a CLI process that produces no output for five minutes by default. The separate total review timeout still applies.
- **Connection recovery.** Temporary network and service failures use bounded retries and backoff. The dashboard distinguishes connection problems, service errors, rate limits, and account issues. A manually paused runner stays paused.
- **Large diff handling.** Git diffs stream to a local file instead of failing at the previous 24 MB output limit. Oversized diffs fail explicitly rather than being silently truncated.
- **Clearer review instructions.** The default prompt keeps unresolved findings visible, groups carried-over non-blocking findings together, and avoids repeated attribution, raw review IDs, and timestamps.
- **Accurate version display.** The dashboard reads its version from the build's package metadata.

### Updating from 1.0.0

Let active reviews finish, quit Review Studio, and replace the app in Applications with this version. Existing local repositories, prompts, settings, and review history are retained. Automatic failed-review recovery is enabled by default; its interval and the inactivity timeout are configurable in Settings.

Existing custom prompts are preserved. To use the revised default wording, compare it with your saved prompt before replacing any project-specific instructions.

Authentication or billing problems still require account repair. Failed publication is not retried automatically, to avoid duplicate GitHub reviews; the saved review remains available for inspection and retry.
