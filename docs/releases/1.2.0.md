### What's new

- **Reviewed PR dashboard.** See the latest verdict and Action line, distinguish current and outdated reviews, and filter by verdict, repository, target branch, or DEV/PROD environment. Sort by activity, review date, or age.
- **Direct access to the latest review.** Open the latest completed review independently of a newer running or failed attempt.
- **Update with base branch.** Bring missing base commits into the PR branch, track the asynchronous request, and queue a new review after the head changes. Pending or uncertain updates block merging.
- **Merge from Review Studio.** Read the latest review and GitHub checks, then choose a merge commit, squash, or rebase. Disabled GitHub methods remain unavailable.
- **Configurable automatic merging.** Add repository rules for an exact target branch, accepted verdicts, and merge method. Automatic merging is off by default. LGTM, NON-BLOCKING, and NON-BLOCKING BUT FIX are separate choices; blocking reviews cannot merge.
- **Merge safeguards and history.** Each merge checks the live PR, reviewed commit and target branch, newer review attempts, checks, permissions, and GitHub requirements. Merge requests use a head-SHA precondition. Interrupted or uncertain requests are recorded and never automatically resubmitted.

- **Dependency maintenance.** Update Electron, the HTTP body parser, and affected build dependencies to compatible patched versions.

### Updating from 1.1.0

Let active reviews finish, quit Review Studio, and replace the app in Applications. Existing repositories, prompts, settings, and history are retained. No automatic merge rules are enabled during the update.

Older reviews remain visible. Reviews created before this version do not record their reviewed target branch, so a fresh review is required before merging them through the app.

Configure rules in **Repositories → Configure → Branches & merging**. Saving a rule authorizes matching existing and future open PRs once their current review is published. Pausing the runner also pauses automatic merging. An in-flight request cannot be cancelled by changing a setting.

GitHub merge queues are not supported by these controls. GitHub's merge API atomically checks the head commit, but does not offer an atomic target-branch precondition; avoid retargeting a PR during a merge. Branches are retained. See [configuration details](https://github.com/naveed-niazi/review-studio/blob/v1.2.0/docs/configuration.md#reviewed-prs-and-merging).
